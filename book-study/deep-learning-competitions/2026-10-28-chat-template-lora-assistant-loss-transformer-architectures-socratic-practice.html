1. Chat Template — Match Training and Inference

The source stresses using the base model's expected conversation template and keeping the formatting consistent between fine-tuning and inference. A model that learned one prompt shape may perform worse when given a different one at inference time.

<system>You are a judge.
<user>Which answer is better?
<assistant>Answer A.
Practice answer: a format mismatch may reduce performance; the model can still tokenize the new text, but the pattern differs from what it was fine-tuned on.

2. LoRA Does Not Split the Pretrained Matrix

LoRA = Low-Rank Adaptation. Keep the pretrained weights frozen and learn a low-rank adjustment, not a decomposition of the original weight matrix.

Weffective= W0+ΔW , ΔW=αrBA

Example: a full update for a 1000 × 1000 matrix would contain 1,000,000 numbers. With rank 8, train two matrices instead:

B∈ℝ1000×8 , A∈ℝ8×1000

That is 8,000 + 8,000 = 16,000 trainable numbers for the update, instead of 1,000,000. The original matrix remains in the computation, but does not receive parameter updates.

Key distinction: LoRA factorizes the learned update into two small matrices. It does not factorize the original pretrained matrix.

3. Assistant-Only Loss — What Is Masked?

The book recommends masking the prompt part of instruction data when training a model to produce assistant responses. The full prompt stays visible as context; only the loss contribution from the assistant's target tokens is included.

Assistant: 4YesIncluded for target answer

In standard decoder-only supervised fine-tuning, the model can compute next-token logits along the full concatenated sequence. A loss mask (often implemented by ignoring labels set to -100) removes user-side target positions from the training objective.

Practice conclusion: the loss is calculated on assistant-token predictions only, but it can backpropagate through computations involving the user's query. The Transformer uses shared trainable weight matrices for the sequence, rather than separate "user matrices" and "assistant matrices".

4. Translation Analogy — Same Target-Only Objective, Different Architecture Paths

In translation, the source sentence plays the role of the user question; the target sentence plays the role of the assistant answer. The target-only loss idea carries over. But the architecture determines how source and target are processed.

Encoder–decoder Transformer

Source (e.g., English) enters an encoder. The decoder predicts target-language tokens (e.g., French) using encoder representations plus its target prefix.

Loss: target predictions only. The encoder does not regenerate the source sentence.

Decoder-only Transformer

Source/prompt and target/response form one sequence during training. Next-token predictions at source-side positions may be computed, but source-side prediction losses are masked.

Loss: target predictions only. At inference, the prompt is supplied as context and the model generates its continuation, not a fresh copy of the prompt.

QuestionPrecise answer
Are translation and question-answering different tasks?Yes.
Must they use different Transformer architectures?No. Either task can use encoder–decoder or decoder-only models.

Source boundary: the book introduces assistant-only loss and summarizes Transformer variants. The comparison of token-level computation in encoder–decoder versus decoder-only training is a clarification developed in this practice.

5. Study Takeaways

LoRA: freeze original weights and train small update matrices. Loss masking: ignore user-token prediction errors while retaining user context. Translation analogy: target-only loss is the common principle; encoder–decoder and decoder-only Transformers implement it differently. Task versus architecture: distinguish what the model is doing from how it is built.
