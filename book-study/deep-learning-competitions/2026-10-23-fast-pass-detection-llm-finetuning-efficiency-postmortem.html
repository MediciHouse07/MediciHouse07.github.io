1. Detection Used for Classification

For some image-level classification tasks, especially medical imaging and industrial defects, the book recommends considering a detector when the decision depends on a localized region. The detector outputs both where a suspected lesion is and how confident it is that the region contains the target.

image-level score=max(box confidences)

In the practice example, confidences 0.18, 0.76, and 0.41 produced an image-level disease score of 0.76.

Checkpoint selection: if the competition scores image-level AUC, select the checkpoint whose image-level probabilities achieve the better AUC, not the checkpoint with the lowest box loss.
Study clarification: classification loss is not the probability itself; it measures class-prediction error against the label. Box regression loss is not the coordinates themselves; it measures error between predicted and target box locations.

2. CNN vs ViT

The fast-pass rule from the book: less data or limited compute tends to favor CNNs; large datasets, strong pretraining, or tasks needing stronger global relationships can favor ViT/Swin. CNNs come with stronger image-specific inductive biases, while Vision Transformers rely more heavily on data and pretraining.

3. Transformer Attention

Attention lets each token directly weight information from other relevant tokens instead of relying on strictly sequential processing. This is the central mechanism underlying the Transformer family used by modern LLMs.

4. LLM Competition Fast Pass

4.1 Data construction

Use the correct chat template, keep training and inference formatting aligned, clean duplicate/garbled text, and protect target quality because the model imitates its training targets.

4.2 LoRA / QLoRA

LoRA freezes the base model and trains small low-rank adaptation matrices. QLoRA combines a quantized base model, typically 4-bit, with LoRA to reduce memory further.

4.3 Training

For multi-turn chat data, mask the prompt when appropriate and calculate loss on the assistant response so training focuses on how to answer rather than how to reproduce the prompt.

4.4 Inference and submission

Estimate single-sample inference time × test-set size and make output parsing robust. A strong model can still fail a code competition through timeout or malformed submission output.

4.5 Metric mismatch

Generation loss may not line up with BLEU, ROUGE, or another competition metric. Best-of-n generates multiple candidates and then selects among them under the task's evaluation logic.

4.6 Decoding

Greedy decoding is stable and deterministic; sampling/top-p adds diversity and is useful when multiple candidates will later be compared or selected.

5. Efficiency and Hardware

The representative idea was gradient checkpointing: save memory by not storing every intermediate activation, then recompute some activations during backpropagation. It trades extra computation for lower GPU memory use.

The book groups this with AMP/bf16, gradient accumulation, smaller batch/input sizes, and selective freezing as practical memory-saving tools.

6. Post-Competition Review

The book's postmortem centers on three questions: where the solution got stuck, which changes genuinely worked, and what the top solutions did that the current approach missed. It also recommends saving code, configs, weights, out-of-fold predictions, and submissions, then updating a personal trick list.
