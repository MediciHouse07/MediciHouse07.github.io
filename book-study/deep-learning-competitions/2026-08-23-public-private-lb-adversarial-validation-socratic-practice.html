1. Public LB vs Private LB

Public LB

A visible score during the competition, based on only part of the hidden labels in the common leaderboard setup described by the source.

Private LB

The hidden portion used for the final ranking. A solution tuned too aggressively to the Public subset can move sharply when the Private ranking is revealed.

Source principle: Public LB is a noisy sample, not the main optimization target. Use CV as the daily decision tool and LB mainly to check whether CV is broadly aligned.

2. Why Leaderboards Shake

The source explains Public LB as a sample-based estimate. If two solutions are extremely close, some of their rank difference can simply be sampling noise. Repeatedly choosing whatever looks best on Public LB risks adapting to that particular subset rather than to the underlying problem.

Submit many variants
Observe Public LB
Prefer Public-noise winners
Private LB reshuffles

3. When CV and LB Disagree

The checklist says to investigate the validation and submission pipeline before assuming the model itself is the only problem. High-value suspects include an inappropriate CV split, data leakage, train/test distribution drift, preprocessing mismatch, and submission-format or ID-order bugs.

Leakage

Training or CV uses information that should have been unavailable, making local validation too optimistic.

Distribution drift

Train and test feature distributions differ, so a random local split may not simulate the real evaluation population.

Pipeline mismatch

Training and inference use different preprocessing, class ordering, IDs, or other mechanics.

4. Adversarial Validation

The source proposes a direct drift test: temporarily label official training rows as 0 and visible test rows as 1, then train a classifier whose only job is to distinguish where each row came from.

train row→0test row→1

Use shared predictor features that exist in both sets. Do not use the true competition target, and do not include a trivial source-indicator feature.

AUC ≈ 0.5

The classifier is close to random guessing, so train and test are difficult to distinguish from the supplied features.

High AUC

The classifier separates train and test easily, which is evidence of distribution drift. Feature importance can help locate which columns drive the difference.

5. ROC Coordinates and AUC

Each point on the ROC curve comes from one classification threshold. For that threshold, compute:

TPR=TPTP+FNFPR=FPFP+TN

The ROC coordinate is (FPR, TPR). Lowering the threshold usually catches more positives, which raises TPR, but it can also create more false positives, which raises FPR.

Useful intuition: AUC ≈ 0.5 means near-random ranking; AUC = 1 means perfect separability for the supplied features.

6. Competition-Format Caveat

Supplemental clarification from the study discussion, not a claim made explicitly by the source: adversarial validation can only compare feature sets that participants can actually see.

Visible evaluation features

If the competition exposes the real evaluation test features while hiding only labels, train-vs-test adversarial validation can directly probe drift against those evaluation rows.

Fully hidden evaluation data

If the real scoring set hides both features and labels, you cannot directly test train-vs-final-evaluation drift. A visible dummy or local test set can only tell you about itself.

7. Session Takeaways

  • Use CV as the main modeling decision tool; Public LB is noisy and can be overfit.
  • When CV and LB diverge, inspect split design, leakage, drift, preprocessing, and submission mechanics.
  • Adversarial validation reframes “train or test?” as a temporary binary classification problem.
  • ROC points are built from threshold-specific FPR and TPR; AUC summarizes overall separability.
  • Adversarial validation only works against feature distributions you can actually observe.
