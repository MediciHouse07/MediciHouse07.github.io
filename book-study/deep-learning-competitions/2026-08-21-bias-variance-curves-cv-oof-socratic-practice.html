1. High Bias and High Variance

The practical diagnostic mapping used in the checklist is:

High bias → underfitting

The model cannot learn the training pattern well. Training performance is poor, and validation performance is also poor.

High variance → overfitting

The model fits the training data very well but changes too much with the particular training sample, so validation performance is much worse.

Ideal case: strong training performance together with strong validation performance suggests both bias and variance are reasonably low.

2. What To Change After the Diagnosis

DiagnosisTypical evidenceDirection to try
High biasTraining and validation both weakMore capable model, better features, or weaker regularization
High varianceTraining strong, validation much weakerMore data, stronger regularization, early stopping, or a smaller model

3. Validation Curve vs Learning Curve

The two curves answer different questions. A validation curve varies one hyperparameter. A learning curve varies how much training data is used.

Validation curve

Use the validation metric that matters for the task—for example F1 if F1 is the competition metric.

Learning curve

If more data narrows a large train–validation gap, that is evidence that additional data is helping reduce variance.

4. Two Layers of Optimization

The session separated two connected but different levels:

Layer 1 — train one model

Hold the setup fixed and run batch → forward → loss → backward → optimizer. The loss trains the model parameters.

Layer 2 — choose the setup

Vary hyperparameters, data amount, or model design; train a model for each setup; then compare those trained models using the validation metric.

Compact distinction: Layer 1 optimizes parameters. Layer 2 searches hyperparameters and training design.

5. Enter Part 1: 5-Fold Cross-Validation

Split the training data into five folds. In each round, train on four folds and validate on the one fold that was held out. Rotate until every fold has been the validation fold once.

Split into 5 folds
Train on 4
Validate on 1 unseen fold
Rotate and average

The average CV score is:

CV score=s1+s2+s3+s4+s55

The reason for using a held-out fold is to estimate generalization on data that the model did not train on.

6. OOF = Out-of-Fold Predictions

OOF stands for Out-of-Fold. It usually refers to the predictions made for the held-out validation fold in each CV round.

After all folds are processed, those validation predictions are stitched back: each prediction is placed back at the original training sample’s position, producing one full-length prediction vector for the training set.

OOF predictions=fold 1 validation predictions+⋯+fold 5 validation predictions
Key property: every sample’s OOF prediction comes from a model that did not train on that sample.

中文直觉：把每一折的验证预测按原训练集的样本位置拼回去，最终每个训练样本都有一个来自“没有见过它”的模型的预测。
