1. High-Recall Ensemble: Raise the Final Threshold

An OR-like ensemble can cast a wide net: if any model raises concern, the sample is treated as positive. This improves recall but also creates more false positives.

Correction step: after the permissive first stage, raise and tune the final threshold on out-of-fold predictions so weak positives are filtered while the required recall is preserved.
ensemble score→search threshold on OOF→best competition metric / recall constraint

2. Kaggle Submission Discipline

Once local cross-validation is reliable, leaderboard submissions should not become the main tuning loop. Local validation drives iteration; submissions mainly check alignment and preserve useful fallback versions.

For Code Competitions, required weights, data, and offline packages must be prepared in advance because the submission environment may have no internet access.

3. More Input Is Not Automatically Better

Images

Higher resolution can preserve small targets and texture, but costs more memory and compute. After a sweet spot, accuracy may flatten.

Long text

Longer context can include more evidence, but also increases cost and may add irrelevant information or truncation/edge problems.

Decision rule: use enough input to preserve the evidence the task needs; do not automatically choose the largest resolution or longest context.

4. High Loss Is a Flag, Not a Diagnosis

A high-loss sample only says the model prediction and the stored target disagree strongly. It does not tell you why. The next step is to inspect the sample and diagnose the cause.

Bad-case loop: find high-loss samples → inspect them → identify the cause → fix one error type → rerun cross-validation.

5. Wrong Label = Data / Annotation Problem

Example: the image is clearly a cat, but the competition training data accidentally labels it as dog. The model predicts cat, yet the loss is high because the code compares the prediction against the stored label dog.

This is label noise: the annotation supplied in the dataset itself can be wrong.

6. Background / Watermark = Shortcut Learning

Suppose most positive medical images happen to contain one hospital watermark. The model may learn:

watermark present⇒disease

instead of learning the lesion itself. The model has learned an irrelevant shortcut. That is what this practice called a feature-learning problem: the model is using the wrong evidence.

7. Long-Text Truncation = Missing Input Evidence

If the model can read only 512 tokens but the answer evidence is at token 700, the later text is removed before the model sees it.

tokens 1–512kepttokens 513–700discarded

The model may fail not because it lacks capacity, but because the necessary evidence never entered the model.

8. One Class Fails: Check Imbalance

If one class has only 50 samples while other classes have 5,000 each, class imbalance is a plausible reason that class performs badly.

Possible fixes include oversampling, class weighting, targeted augmentation, or more data for that class.

9. Low Train Loss + High Validation Loss = Overfitting

If training loss is very low but validation loss remains much higher, the model has learned the training data better than it generalizes to unseen data.

Diagnosis: overfitting. Typical responses include stronger regularization, early stopping, more data, or a smaller/more stable model.
