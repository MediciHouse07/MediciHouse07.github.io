1. High-Recall Ensembling: Raise the Final Threshold

A permissive first-stage ensemble can catch more positives, but it also creates more false positives. The next step is to tune a stricter final threshold on out-of-fold predictions.

ensemble score→search threshold on OOF→best metric / required recall
Rule: if false positives become too numerous, the final threshold generally moves higher. The threshold is validated on OOF predictions rather than guessed.

2. Kaggle Submission Discipline

When local cross-validation is reliable, Kaggle submissions should not become the main tuning loop. Local CV drives iteration; leaderboard submissions are used more sparingly for alignment checks and fallback coverage.

3. More Input Is Not Automatically Better

Images

Higher resolution can preserve small details, but memory and compute rise sharply. Once validation accuracy stops improving, a larger resolution may only add cost.

Long text

Longer context can preserve useful information, but it can also add irrelevant content, cost much more compute, and create truncation or long-context weaknesses.

Shared principle: find a useful input sweet spot instead of blindly maximizing resolution or context length.

4. Error Analysis: High Loss Is a Flag, Not a Diagnosis

A high-loss sample only tells us that the model prediction and the stored target disagree strongly. It does not by itself tell us why. The next step is to inspect the sample and classify the cause.

Data problem

The provided annotation itself may be wrong or noisy.

Model-learning problem

The model may have learned an irrelevant shortcut instead of the real evidence.

Input-pipeline problem

The information needed for the answer may have been removed before reaching the model.

5. What “Wrong Label” Means

It can literally mean the competition training annotation is incorrect.

Example: the image is clearly a cat, the provided label says “dog,” and the model predicts “cat.” The loss is high because the code compares against the stored label “dog.” The model may be reasonable while the annotation is wrong.

This is label noise: an issue with the training data supplied to the model, not automatically evidence of underfitting or overfitting.

6. Background / Watermark Shortcut Learning

A model can learn an accidental clue that correlates with the label. For example, if most positive X-rays contain one hospital watermark, the model may learn:

watermark⇒disease

instead of learning the actual lesion. This is a shortcut-learning problem: the model has learned the wrong feature.

7. Long-Text Truncation

If a model accepts only 512 tokens but the crucial evidence appears at token 700, that evidence never reaches the model.

tokens 1…512✓tokens 513…700✗

The resulting error is an input/truncation problem, not necessarily a capacity problem.

8. One Class Fails Repeatedly

If one class has far fewer examples than the others, class imbalance is a plausible cause of systematic misclassification. Typical remedies include oversampling, class weighting, targeted augmentation, or additional data.

Diagnostic order: inspect whether the class has enough useful data before blindly tuning the learning rate or increasing model size.

9. Low Training Loss + High Validation Loss

This is the standard overfitting pattern: the model fits the training set very well but generalizes poorly. Typical responses include dropout, weight decay, early stopping, Exponential Moving Average, or more data.

10. The Bad-Case Loop

find error pattern→identify cause→fix one thing→rerun CV

The goal is to replace random trick hunting with targeted repair.
