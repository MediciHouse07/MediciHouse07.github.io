1. The Five-Part Training Loop

1. Batchfeed a small group of training samples
2. Forwardrun the current model and produce predictions
3. Lossmeasure how wrong those predictions are
4. Backwardcompute gradients for the parameters
5. Optimizeruse gradients to update the parameters
Key distinction: backward computes the gradient; the optimizer performs the parameter update.

2. A Linear Model Makes the Loop Concrete

Use a simple model:

y^=ax+b

Forward means evaluating the model with the current a and b. A regression loss can then be written as squared error:

L=12(y^−y)2

Backward computes gradients such as:

∂L∂a=(y^−y)x,∂L∂b=y^−y

The optimizer then uses those gradients:

anew=aold−η∂L∂a
Mental model: forward answers the question, loss grades the answer, backward produces the error-attribution gradients, and the optimizer applies the correction.

3. Batch, Step, and Epoch

Batch

A small subset of training samples processed together.

Step

One batch is processed and one parameter update is made.

Epoch

The complete training set has been passed through once.

Why multiple epochs?

One pass may not be enough to learn; too many passes can lead toward memorization and overfitting, which is why early stopping is useful.

For 10,000 samples with batch size 100:

10000100=100 steps per epoch

Five epochs therefore produce:

5×100=500 total steps

4. Batch Size and Gradient Noise

The checklist’s intuition is that batch size determines how many samples contribute to each gradient estimate.

Small batch

Fewer samples per update means a noisier gradient estimate. It uses less GPU memory, and the noise can sometimes help generalization.

Large batch

More samples per update gives a steadier gradient estimate and higher throughput, but uses more GPU memory.

If GPU memory cannot hold a large batch, the source introduces gradient accumulation. For physical batch size 32 accumulated across four mini-batches:

effective batch size=32×4=128

The four gradients are accumulated first; the optimizer updates the weights once after the accumulation window.

5. Learning Rate: Step Size, Not Direction

The gradient determines the local direction. The learning rate determines how large a step the optimizer takes:

θnew=θold−η∇L

Learning rate too large

The optimizer can overshoot, oscillate, or even diverge.

Learning rate too small

Loss may still decrease, but training becomes extremely slow.

6. Warmup and Cosine Decay

The session corrected one subtle intuition: training often uses a relatively high learning rate early and lowers it later, but many modern schedules insert a short warmup first.

Warmup
very small LR → target LR
Normal training / cosine decay
target LR → gradually smaller LR
0↗ηmax↘0

The checklist describes warmup as commonly taking roughly the first 5–10% of steps. After warmup, the learning rate begins decreasing; cosine decay is presented as a common default.

7. Momentum: Remembering Previous Gradients

Without momentum, the update reacts mainly to the current batch. Momentum keeps an accumulated velocity:

vt=βvt−1+gt
θt=θt−1−ηvt

If successive gradients point in roughly the same direction, momentum reinforces that direction and accelerates movement. If β=0, the previous velocity is forgotten. The checklist gives about β=0.9 as a common value, while very large momentum such as 0.99 can carry too much inertia and cause overshooting or oscillation near the optimum.
